# 第10章 将工具调用与工作流建模为决策任务

> 读前回顾：[第02章](02-rl-foundations.md) · [第05章](05-llm-post-training.md)

问数助手写出了合法 SQL，任务却还没结束。它可能查错时间范围，也可能需要核对字段含义。要完成任务，它得在生成文字之外，选择工具、读取结果，并决定下一步。

训练这样的 Agent，首先要把“下一步”写清楚：哪些信息可见，哪些动作可选，什么时候应该停下。

## 10.1 定义观测与工具动作

把问数任务摊开，动作清单并不只有“生成 SQL”：查看表结构、执行只读查询、修改参数、请求澄清和停止，都可能决定成败。策略能看到用户需求、工具返回、历史操作与剩余预算；尚未查询的数据、真实故障原因和用户未表达的意图，则仍藏在环境中。

建模可以从一条真实形态的任务走查开始。用户要求统计“活跃客户上季度交易”，策略先查看字段定义，得到活跃口径；再查询日历区间，确定季度边界；最后执行只读查询并检查结果。这里每次观察都来自已执行动作，策略不能提前读取尚未查询的证据。

如果把环境中的全部数据库字段直接放进观测，任务会变容易，却可能与部署条件不同。相反，如果省略工具报错和此前查询，策略便无法知道为何需要修复。观测设计的目标是保留决策所需信息，并遵守真实可见范围。

## 10.2 选择训练对象与动作粒度

接下来要决定，究竟让谁学习这些选择。若只需改善“下一步选哪个工具”，小型结构化控制器可能已够用；若参数生成、信息解释和规划都需改善，可以研究语言模型策略。训练范围越大，所需样本与资源也越不同，应各自与固定流程比较。

决策粒度也影响信用分配。把整段回答视为动作，轨迹较短但反馈粗；把所有 token 视为动作，表达细却增加训练长度。实用设计通常同时记录生成 token、工具调用和任务轮次，以支持不同层级的分析。

还可以分开工具路由与参数生成。例如控制器只选择“查看结构”还是“执行查询”，参数由固定规则或冻结模型补全。这样便能先检验时机选择是否存在学习空间。若控制器有效，再逐步放开参数生成，实验归因会更清楚。

动作粒度决定了环境一次推进多远。把“完成一次查询”作为宏动作，训练轨迹较短，但其内部错误恢复被隐藏；逐 token 训练表达更灵活，却需要处理更长的序列。应先写清究竟要优化哪些决策，再选择粒度。

## 10.3 将停止、求助与权限纳入环境

动作空间必须包含停止与求助，否则系统可能只能继续调用。只读、写入、外部发送等动作应由运行系统分别执行权限校验。训练奖励可以鼓励遵守边界，实际权限由工具执行层落实。

停止并不等于放弃。证据已经充分时继续查询，只会增加成本；证据不足又无法可靠补充时，求助可能是合理选择。若动作空间只有继续调用，策略即使知道应该结束，也没有办法表达。

执行层还应区分建议与真实副作用。生成“删除”参数，并不应绕过工具权限；策略奖励只提供学习倾向，动作是否合法需要在执行前确定。把这些规则写进环境，也有助于训练与部署保持相同语义。

## 10.4 写出一个最小任务规格

| 字段 | 问数助手示例 |
| --- | --- |
| 可见信息 | 需求、已查表结构、查询历史、剩余预算 |
| 合法动作 | 查看元数据、只读查询、澄清、提交、求助 |
| 成功条件 | 口径、时间范围与查询结果均通过核验 |
| 失败/截断 | 明确错误、预算耗尽或外部超时 |
| 训练对象 | 工具控制器，或产生动作的语言策略 |

剩余预算应进入观测：同样的报错，在还剩十步与只剩一步时可能需要不同选择。若遗漏这类信息，相同输入会对应冲突的合理动作，策略学习就更困难。

可进一步把任务规格写成一条可检查的转移：当前预算为3，已知表结构，尚未执行查询；选择一次只读查询后，预算变为2，观测增加结果与时间范围。若工具超时，应明确是否消耗预算、能否重试、结果是否仍可能晚到。

看似工程细节的约定，会改变最优动作。超时后免费无限重试的模拟器，会鼓励与真实系统不同的行为；重复查询若能免费获得独立随机结果，也可能产生新的投机路径。任务规格因此是学习问题的一部分，而不只是接口文档。

**例：一次报错后的三种选择。** 当前观测提示日期字段不存在，已查元数据表明正确字段名为 `event_date`，还剩两次调用。此时修改字段重试，具有观测支持；再次查看同一份结构，可能只增加成本；直接提交原结果，则没有完成依据。

若正确字段尚未知，同样的报错就可能应先查结构。两个任务表面错误相同，合理动作却因历史不同而变化。这个例子说明，动作策略需要以当时可见信息为条件，而不能只按错误关键词固定奖励“重试”。它也为数据构造提出要求：训练集要同时覆盖这两种情境，才能检验策略是否学到了区分。
