# 第12章 训练环境、轨迹与可复现交互

> 读前回顾：[第10章](10-agent-task-modeling.md)

同一套策略，昨天能完成任务，今天却在第五次调用时卡住了。是模型变了，工具变了，还是上一次任务留下了状态？如果环境说不清这些差异，训练也很难积累可靠经验。

一个可学习的环境，需要让动作有明确后果，让任务能够重新开始，让成功与失败都能被追溯。

## 12.1 重置、动作与结束语义

一次任务开始时，环境重置并给出观测；策略执行动作后，环境返回结果与奖励；到结束时，还需说明是成功、失败，还是外部条件打断。[Gymnasium](https://gymnasium.farama.org/api/env/)将任务自然终止与外部截断分开。这个区别会影响价值目标：被时间限制打断，不一定意味着后面再无价值，是否自举仍取决于任务定义。

一个最小环境可以理解为两个函数：重置给出初始观测，执行动作给出下一观测、奖励与结束标记。输入输出越明确，就越容易检查奖励对应哪次动作、预算何时减少，以及任务结束后是否还在继续采样。

尤其要区分业务预算与采样上限。若预算耗尽本来就定义为任务失败，它属于任务结束；若采样器为控制批次长度而暂停了仍可继续的任务，可能只是截断。相同的“达到步数上限”，因任务约定不同而有不同含义。

## 12.2 验证目标状态

屏幕上出现“调用成功”，往往只说明工具做完了它那一小步。查询可能执行无误，却选错对象或时间范围。环境还需要检查目标状态和证据，才能判断整个任务是否完成。

验证目标状态时，应尽量读环境的真实结果。例如查询助手提交统计答案，环境核对实体、时间和聚合口径；文件任务则检查目标文件的内容或状态。只分析助手在最后说了什么，容易把“声称完成”误判为完成。

对于无法完全自动判定的任务，可以组合可执行检查和人工抽查，并记录未知状态。把尚未获得标签的任务一律算失败或成功，都会扭曲训练与评估分布。

## 12.3 记录可恢复的轨迹

轨迹至少记录：任务ID、观测引用、动作与参数、工具返回、耗时、奖励分项、终止原因、策略/环境版本；语言策略还需记录 token 掩码与行为 log-prob。异步工具要保留调用ID、实际完成时点及重试关系，避免把乱序返回接到错误动作上。

轨迹记录还需支持因果顺序。若两个工具并发调用，第二个先返回，策略当时只能看到已完成结果；不能在回放时把后来才出现的信息补到更早观测。工具调用ID与时间戳，正是为了恢复这种可见性。

语言策略还应保留实际使用的模板、分词与生成配置。概率对应的是特定 token、特定前缀和特定策略版本；只保存最后拼接的文本，可能无法重新得到训练所需概率。记录是否充分，应由准备采用的更新方法来检验。

## 12.4 环境真实性与复现边界

快照与随机种子有助于复现，但无法固定所有外部服务。训练可使用可重置模拟器，独立测试再加入真实接口或冻结快照。训练、验证、测试应按任务来源和模板隔离，而不是仅将同一任务随机打散。

复现可分为几个层次：相同输入能否还原相同工具结果，相同配置能否得到相近训练表现，换一组任务能否仍支持同样结论。固定种子主要帮助前两类检查的一部分，不会自动提供第三类泛化证据。

模拟环境可以提高前两类可控性，真实接口测试则检验失真。比较时应指出哪些随机性来自策略、任务生成与外部服务。否则一次工具故障引起的下降，可能被误判为算法退化。

## 12.5 环境先通过哪些检查

对同一快照执行相同动作，应在确定性设置下得到相同结果；非法动作应按约定拒绝；重置后不应残留上一个任务状态；预算变化与日志应一致；终局标签不能通过工具返回的无关字段泄漏。

对于只读查询任务，数据不变也不代表环境状态完全不变：已获取的证据、剩余预算和待完成调用都属于需要恢复的交互状态。回放若只恢复数据库而遗漏这些内容，候选动作就不再处于相同条件。

环境检查最好包含反例。提交空答案时不能成功，查询其他任务实体应被拒绝，重复重置不能累积奖励，评分字段不能直接暴露标签。若这些检查失败，策略可能先学会环境漏洞，再学会任务本身。

还可用固定脚本走一条已知成功路径与一条已知失败路径，检查两者的奖励和结束状态。它们不是训练结果，却能证明环境基本语义一致。先完成这种小规模检查，再连接大模型，通常能减少许多难以定位的问题。
