# 第05章 大模型后训练的统一视角

> 读前回顾：[第02章](02-rl-foundations.md) · [第04章](04-policy-gradient-ppo.md)

同一个模型，既可以从标准答案中学习，也可以比较两份回答，还可以把写出的代码交给测试。它们都叫后训练，训练信号却各不相同。

读懂 SFT、DPO、RLHF 和 RLVR，关键是分清：反馈从哪里来，算法怎样利用反馈，以及哪些参数真的发生了变化。

## 5.1 文本生成如何成为决策任务

把“下一步往哪里走”换成“下一个 token 写什么”，文本生成就接上了决策语言：问题与已生成前缀构成观测，下一 token 是动作，完整回答是一条轨迹。也可以把整段回答当作较粗粒度的动作；加入工具后，回答又成为外部交互中的一步。

这种映射还揭示了语言生成中的一个特点：当前 token 会进入后续前缀，影响下一次决策。例如前面选错了变量名，后面可能需要维持这个错误，也可能主动修正。即使奖励只在回答结束时给出，训练仍然要处理一系列有依赖的动作。

在多轮工具任务中，一次模型输出之后还会插入环境观测。模型可以决定调用哪个工具、传入什么参数，却不能决定工具真实返回的内容。训练轨迹需要保留这个边界，避免把观测当作模型动作学习。

## 5.2 训练信号与优化方法

| 路径 | 训练信号 | 主要作用 |
| --- | --- | --- |
| SFT | 高质量目标回答或轨迹 | 学习格式、知识表达与已有行为 |
| DPO | 同题优劣回答对 | 从相对偏好直接更新策略 |
| RLHF / RLAIF | 人类或 AI 反馈形成的评分 | 提供偏好导向的奖励 |
| RLVR | 程序、规则等可验证反馈 | 在可检验任务上评价生成结果 |

这些缩写之所以容易混淆，是因为它们回答的并非同一个问题。RLHF 常先收集人类偏好、训练奖励模型，再优化策略；RLAIF 强调 AI 反馈来源；RLVR 强调结果能够验证。PPO、GRPO 才是在说怎样更新策略。读一条训练配方时，把“反馈”与“算法”分别标出来，就容易理解了。

预训练主要从大规模文本学习预测规律；SFT 使用选定示范，让模型更经常给出期望回答。偏好学习进一步提供“两个答案中哪个更好”的信号；交互式 RL 则可以在当前策略采样后评价并更新。它们改变了数据如何获得，也改变了学习目标。

因此，“使用了奖励”还不足以描述完整训练。奖励由人标注、模型预测还是程序验证？回答来自固定数据还是当前策略？优化采用 DPO、PPO 还是组相对方法？把这些维度分别写清楚，配方才具有可比较性。

## 5.3 一次后训练涉及哪些模型

语言模型 PPO 的典型组件是 Actor、Critic、奖励模型和参考模型。验证器可替代奖励模型；部分方法不需要独立 Critic。参考模型通常固定，用于衡量偏离起点的程度；它与负责采样的旧策略承担不同职责。

典型 RLHF 迭代中，Actor 生成回答，奖励模型给出分数，Critic 预测回报，参考模型用于正则比较。它们可以共享部分底座或以不同资源配置部署，但逻辑职责需要分开。将“同时装进显存的模型数”直接当作算法成本，会忽略共享、卸载和采样配置。

奖励模型与 Critic 尤其容易混淆。前者评价一个输出有多好，后者预测从某个前缀继续执行当前策略的回报。任务和奖励不变时，Actor 更新仍会改变后续行为，Critic 因而也需要跟上。

## 5.4 训练与推理计算如何组合

[DeepSeek-R1 技术报告](https://arxiv.org/abs/2501.12948v2)展示了冷启动数据、强化学习、拒绝采样和蒸馏的组合路径。其意义在于提供可研究的训练配方，不能据此推导所有底座、任务都适合跳过 SFT。

推理时多采样、投票或搜索可以提升单次任务表现，但未必更新参数。比较时应分别报告训练成本与测试时计算，避免把两类收益混在一起。

设模型一次作答正确的概率不高，多采几个答案再用测试筛选，可能提高交付质量，却增加推理成本。训练则希望改变这个生成分布，使部署时更容易直接获得好答案。两种投入可以配合，但解决的是不同阶段的问题。

比较两个训练方案时，最好先固定部署策略：是否允许多采样、最多生成多少 token、是否使用工具和重排序。若训练方案同时扩大测试预算，就很难知道提升来自参数更新还是额外尝试。

## 5.5 用一个代码任务串起训练阶段

设任务是实现字符串去重函数。SFT 用示范教会模型遵循接口与输出格式；偏好数据可以比较两段实现的清晰程度；RLVR 通过运行测试评价正确性；PPO 或 GRPO 再利用这些分数更新策略。部署时仍可生成多个候选、运行测试后选择，这部分属于推理计算。

这条链路不是必须全部执行。若 SFT 已满足要求，就应先记录基线；若模型常生成非法格式，继续提高测试奖励并不能替代对基础行为的学习。

以字符串去重任务为例，先把接口签名、顺序要求和边界输入写清楚。SFT 示范提供一种满足要求的实现；偏好对可以进一步比较可读性，但两份实现都需先通过正确性检查。RLVR 让当前模型生成新实现，再通过验证反馈改进分布。

蒸馏则可以把教师在较高计算预算下产生的成功实现用作学生示范。学生最终应在独立函数和输入上评估，才能判断学到的是解决任务的规律，还是训练题目的表面模板。整个流程中，数据来源与测试隔离始终和算法同样重要。
