# 第28章 方法选型、研究地图与学习路线

> 读前回顾：[第01章](01-why-rl.md) · [第03章](03-algorithm-map.md)

学到这里，面前已经有不少方法。真正做项目时，起手式仍然应是看清眼前的失败：不会用工具、奖励不可靠，还是队友换了就无法配合？

这一章把方法重新放回这些问题中，也给出继续读论文、做实验的路线。

## 28.1 从失败类型选择方法

| 主要瓶颈 | 先做什么 | 值得进一步研究的方向 |
| --- | --- | --- |
| 基础行为不会 | 示范、工具与 SFT | 课程、数据覆盖 |
| 偏好无法满足 | 检查标注与偏好基线 | DPO、奖励建模 |
| 可验证任务表现不足 | 检查验证器与采样成功率 | PPO/GRPO及针对性改进 |
| 长任务常失败 | 检查状态、轨迹与恢复行为 | 分层信用、过程反馈、异步训练 |
| 多角色协作无收益 | 等预算单主体与固定编排 | 角色贡献、通信、联合训练 |
| 无法获得新交互 | 检查日志覆盖与模仿基线 | 离线 RL 与保守评估 |

同一个表面失败可能来自不同层次。例如所有复杂题都失败，可能是基础知识不足、任务不可完成，也可能是验证器不接受正确格式。没有先排除这些原因，直接更换优化方法，通常难以得到可迁移认识。

方法选择因此可以看成逐步缩小问题：先判断信号是否正确，再判断成功行为是否可采到，最后判断更新是否在扩大这些行为。每一步都对应不同证据，也决定下一篇论文是否值得优先阅读。

## 28.2 判断研究证据

读论文时，不妨先停在实验设置页：作者遇到了哪种失败，改了什么，哪些条件保持不变，成本怎么算，哪些任务没有改善？再看代码与版本是否足以复核。带着这些问题回看最终分数，才能判断它对自己的项目有没有参考价值。

机制主张与效果主张应分开检查。“改变序列权重”可以由目标函数与代码直接核对；“因此更高效”则需要任务、预算和实验支持。理论分析还要检查策略类、奖励假设及优化条件，不能仅凭定理名称推广到大型系统。

复现也有层次：重新运行作者配置、用相同数据重现趋势、在新任务验证机制，都提供不同证据。一个仓库有脚本，不等于关键数据和环境已完整公开；无法复现时，应具体记录缺少了什么。

## 28.3 开放问题与学习路线

2026年11月的[覆盖退化与参考重置研究，v1](https://arxiv.org/abs/2611.14467v1)指出，在所分析的设定中，奖励改善仍可能伴随优质回答覆盖下降；并在 softmax 线性策略等假设下研究参考重置的收敛性质。它提醒我们关注输出支持与探索，但尚不能据此宣称大型 Transformer 的实际训练获得同样保证。

学习路线可分三条：大模型方向重点读04—09、22—24；Agent 方向读10—13并补齐环境和约束；多主体方向读14—18再做27章对照。共同起点是独立跑通一个小任务，共同终点是解释改进来自哪里。

当前值得持续研究的难点，往往跨越算法与系统：长任务如何获得有效成功经历，角色怎样在变化队友中保持能力，奖励怎样接近真实目标，异步采样怎样兼顾成本与分布一致性。它们很少能由一个损失项独立解决。

阅读前沿材料时，可以把新方法放进这些问题中。先确认作者解决的是哪个局部困难，再看它是否要求新的环境、数据或计算。这样既能跟进研究，也能避免频繁换名词却没有积累理解。

## 28.4 以可完成的任务安排学习

先完成一个能解释价值更新的小环境；再追踪一次语言模型的采样、奖励、优势与掩码；随后加入工具状态与异常；最后才比较多角色训练。每一步保留最小基线和失败样本。

学习阶段可以暂缓复杂证明，但不能跳过数据由谁采样、奖励怎样产生、哪些参数更新。读懂这三件事，比记住更多缩写更有助于迁移到新方法。

学习路线可为每个阶段留下一个小产物：基础阶段手算一次价值更新；后训练阶段画出三个策略的数据流；Agent 阶段保存一条可恢复轨迹；多主体阶段完成一次跨队友评估。产物不必庞大，但应能检验自己是否真的理解。

当一个问题可以用自己的小例子解释，再回到论文公式，阅读负担会小很多。进阶的关键不是把每个分支都同时学完，而是能够指出某个方法的前提、机制与证据，并据此提出下一步实验。

不妨为自己选定一条主线。若关注大模型后训练，先能手算组优势，再核对一次完整更新；若关注 Agent，先让环境可重置并能解释结束；若关注多主体，先在两角色、结构化消息下检查协作。三条路线共享基础，但最先需要的实验产物不同。

读完一章后，可以尝试解释一个没有在书中出现的新例子。若只能重复定义，遇到新任务仍不会写观测、动作和反馈，说明概念尚未变成可用工具。回到小例子补足这一步，通常比继续增加阅读量更有效。

最后一篇把这些判断带入银行场景。先找出值得优化的决策，再沿着一个合成调查案例，走完从试点问题到验证方案的过程。
