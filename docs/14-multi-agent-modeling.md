# 第14章 多智能体问题建模与协作机制

> 读前回顾：[第02章](02-rl-foundations.md) · [第03章](03-algorithm-map.md)

一名调查者看客户资料，另一名查看事件记录。如果两边交换关键证据，可能更快完成任务；如果各查各的、反复等待，增加人手反而会拖慢进度。

多智能体强化学习研究的，正是多个决策者怎样在彼此影响中学习。角色数量只是起点，信息、目标和协作方式才决定问题的形状。

## 14.1 联合动作与局部信息

把两个调查者的动作放在同一个环境里看，一方查询或发消息，会改变另一方接下来能做的事。Markov Game 用联合动作描述这类相互影响，也允许各主体有不同奖励；合作型 Dec-POMDP 则强调主体在局部观测下追求共同目标。客户、交易与关联信息分别掌握在不同角色手中，就是一个直观例子。

在合作任务中，可以把所有主体的动作写成联合动作 $(a_1,\ldots,a_n)$，环境根据它们共同转移。即使主体轮流行动，这种相互影响仍存在。某角色发送摘要，会改变下一角色的信息；某角色过早终止，也可能使团队无法补救。

不同奖励结构会形成不同问题。共享奖励强调团队目标，独立奖励可能引入竞争，二者混合则需要说明冲突怎样解决。角色提示中写着“合作”，不等于优化目标已经一致。

## 14.2 系统多角色与策略学习

| 系统 | 谁决策 | 是否训练协作 |
| --- | --- | --- |
| 单 Agent 调多个工具 | 一个策略统一控制 | 可训练单策略 |
| 固定多角色工作流 | 人工规定路由与角色 | 角色可以完全不训练 |
| 多主体策略学习 | 多个角色策略影响联合轨迹 | 明确更新共享或独立参数 |

若一个统一控制器看到全部信息、直接选择所有工具动作，可以先将其建模为集中式单策略。若主体拥有不同观测与权限，需要分别决定动作，就有理由研究多主体结构。二者都能完成复杂任务，区别在于控制与信息如何分配。

固定编排也可以非常有效。规划、执行、检查按人工规则衔接，即使没有联合训练，也可能改善结果。实验中应保留这类基线，才能区分角色结构的收益与学习协作的收益。

## 14.3 为什么共同学习更困难

单个智能体学习时，可以暂时把环境看作稳定对象；队友也在更新策略时，这个前提就变弱了。同样的消息，昨天的队友会执行，今天的队友却可能要求澄清，这就是非平稳性的一种表现。组合规模也在增长：每人有 $m$ 个动作，$n$ 人可能形成 $m^n$ 种联合动作。加上局部信息，团队失败更难归因。

当任务可以清楚拆分、角色拥有互补信息或权限、并行处理确有价值时，多主体值得研究。若单策略已经能低成本完成任务，增加角色可能只增加上下文重复与错误传播。应先建立等预算的单主体基线。

非平稳性可以通过一个通信例子理解。训练早期，执行者把“范围已确认”理解为时间和实体都确认；后来队友只用它表示时间确认。同一句消息的后果变了，旧轨迹便不再完整代表当前协作。记录队友版本，可以帮助定位这种变化。

联合动作空间也不仅影响搜索，还影响数据覆盖。两名主体各自见过某个动作，并不说明它们见过该动作组合。团队失败可能发生在单个动作都合理、组合却冲突的情境，这正是协作学习需要处理的部分。

## 14.4 一个合作问题的最小建模

两名调查者分别看到客户信息与事件信息，各自决定是否补充查询、发送摘要或停止，团队奖励取决于最终结论和总成本。单个调查者的合理动作取决于队友将发送什么；若队友策略持续变化，旧经验的含义也会变化。

可以共享一套策略参数，并输入角色与局部观测；也可以为两个角色分别训练。共享参数不等于共享信息，角色观测仍应按任务规则隔离。

为两个调查者建立最小环境时，可先只允许三类动作：查询各自信息、发送结构化摘要、提交建议。环境记录双方的局部观测、消息和总预算，终局评价证据是否足够支持结论。这样可以先研究信息交换，而不让自由文本生成掩盖主要问题。

随后分别比较：不通信、固定通信规则、学习通信选择。若固定规则已经达到相同质量和成本，就没有证据证明更复杂训练值得引入。主体是否增多，应由任务需要和实验结果决定。

这个小环境还可以设置两种信息条件。第一种，两名主体都能直接看到全部证据；第二种，各自只有一部分，必须通信。前者适合检查动作冲突，后者才真正要求信息交换。若两种条件被混在同一结果中，就难判断协作收益来自哪里。

再把一方策略冻结，只训练另一方，可以先观察它能否适应固定队友。随后允许双方更新，比较学习速度与跨队友表现。这样逐步增加非平稳性，比直接训练大型团队更容易看清问题的来源。
